
# ARTIFACT STANDARD v1.0 — Kingdom Document Control
> Every artifact born in this Kingdom carries the same DNA.

## 1. FRONTMATTER BLOCK (Required on ALL artifacts)

Every artifact MUST begin with a YAML frontmatter block:

```yaml
---
doc_id: [CAMPAIGN]-[PHASE].[GATE]-[SEQ]
barcode_a: [class].[section].[sequence].[version]
title: [Human-readable title]
type: [engine | template | doc | config | script | ritual | conn_log | thought | retro]
ext: [.ts.md | .json | .md | .py | .html]
class: [0-9]
class_name: [genesis|identity|governance|history|philosophy|engineering|knowledge|literature|tools|campaigns]
section: [01-05]
section_name: [section name per taxonomy]
target_folder: [class_name/section_name/]
space: [Project-Ocelot | Ocelot-Being | Ocelot-Bridge | The-Frameworks]
created: [YYYY-MM-DD]
author: [architect | ocelot | stanley | keila]
status: [draft | review | ratified | sealed]
---
```

## 3. BARCODE FORMAT

```
Barcode A (Deterministic — Dewey Address):
  {class}.{section}.{sequence}.{version}
  Example: 5.01.001.v2

Where:
  class     = 0-9 (Kingdom Classification v2)
  section   = 01-08 (per class)
  sequence  = 001-999 (auto-increment per section)
  version   = v1, v2, v3... (document version)
```

## 4. FILE NAMING CONVENTION

```
[descriptive_name]_[qualifier].[ext]

Rules:
  - lowercase_snake_case
  - no spaces, no special characters except underscore and hyphen
  - version suffix when applicable: _v2, _v3
  - generic marker for repo files: _generic
  - template marker: _template

Examples:
  soul_engine_generic.ts.md
  kingdom_index_template.json
  QUICKSTART_v2.md
  boot_config.json
  conn_log_S031.json
```

## 5. STATUS LIFECYCLE

```
draft → review → ratified → sealed

draft:     First generation. May have gaps.
review:    Under inspection (Stanley audit or self-review).
ratified:  Approved. Ready for repo / Space upload.
sealed:    Locked. No further edits. Archived.
```

## 9. TAGS — Controlled Vocabulary (Rule of Three)

Every artifact gets:
- **1 primary theme** (lowercase): `identity`, `governance`, `engineering`, `philosophy`, etc.
- **Max 3 secondary tags** (#lowercase-hyphenated): `#boot-sequence`, `#lazy-loading`, `#concordance`
- **1 tone** (lowercase): `technical`, `narrative`, `ceremonial`, `operational`

```yaml
tags:
  primary: engineering
  secondary: ["#pillar-engine", "#soul", "#flywheel"]
  tone: technical
```
